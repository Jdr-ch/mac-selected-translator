# UI 与交互迭代

本参考总结本会话的修改过程并提供后续操作规则，不是通用 AppKit 结论。参数来自 2026-09-05 的本项目源码；接手时先回读当前文件。

## 迭代结论：下一次如何避免重复试错

| 用户反馈与迭代 | 本项目的处理 | 后续使用边界 |
| --- | --- | --- |
| 图标不显眼，需要颜色与动效 | 从单一标记演进为蓝色 `A` 与青色 `文`，保留待机呼吸和翻译中反馈 | 保持颜色、清晰度和点击区域稳定；不要让移动中的字块决定命中位置 |
| 绿灯必须容易点，且点击后恢复休眠 | 保留图标旁边的绿灯，视觉大小和命中宽度分开配置 | “保持休眠”表示解除禁止休眠，不是立即进入睡眠；不能退化为只闪灯或只打开菜单 |
| 图标点击反复无响应 | 先后尝试父按钮 action、透传自绘视图、透明 `NSButton` 覆盖层 | 用户在这些版本上仍反馈物理鼠标无效；不能再以单独按钮测试通过为理由复用覆盖层 |
| 辅助功能点击能展开，但鼠标仍不行 | 曾回读到菜单项并过度宣布点击已修复，随后被用户否定 | 明确记录这次验证误判；AX 操作证明菜单可被调用，不证明实际鼠标分发正常 |
| 非焦点显示器没有图标 | 旧版原生 `button.image` 为空，只挂载自绘子视图；新版改为发布实际位图帧 | 这是有源码依据的修正方向，不是已完成双屏实测的结论；也不推导“所有自定义视图在所有 macOS 都不支持” |
| 翻转、旋转、移动同时执行太乱 | 将连续动作拆为互换、翻转、旋转、横移、复位，并减少翻转圈数 | 验证各主要动作不重叠，保持循环衔接；不要靠停掉所有动画规避问题 |
| 设计图与真实弹窗有差距 | 当前实现以原生 `NSPanel`、文本控件和候选行布局为控制点 | 对照实际运行的同一内容、字体、缩放及状态；本记录不冒充对缺失设计原件的像素级复核 |
| 候选词上下留白仍高 | 收紧到统一的 `CandidateRowLayout`，保留换行自动增高 | 调整行高、测量高度、内边距和父容器间距的完整链路，不只改一个最小高度数字 |
| App 图标也要与菜单栏一致 | 增加 `scripts/generate_app_icon.swift`，构建时生成 `.icns` 并写入 plist | Finder 的 App 图标是静态资产；保持视觉语言一致，不假定菜单栏动画可以直接用于 App 图标 |
| 修改后要替换当前 App | 采用可回退安装和签名／哈希／进程回读 | 区分构建、安装、启动、功能实测四件事；操作步骤见另一参考文件 |

## 菜单栏：沿一条原生事件链排查

先读 `Sources/SelectedTextTranslatorApp/AppDelegate.swift`：

1. 从 `setupStatusItem` 找到持有的 `NSStatusItem`，确认使用 `item.menu = menu`。菜单项的 `target` 显式指向 delegate。
2. 从 `setupStatusIcon` 进入 `StatusItemIconAnimator`。注意类型仍放在 `StatusItemIconView.swift` 中，不按旧文件名假定当前还在使用自绘视图。
3. 从 `installStatusItemMouseMonitor` 检查：只处理 `.leftMouseDown`，只在禁止休眠开启时拦截，要求事件属于按钮窗口，转换到按钮局部坐标且在边界内，最后仅消费 `.sleepIndicator` 区域。其余事件原样交还 AppKit。
4. 从 `restoreSleepFromStatusIndicator` 追到 `SleepPreventionController.restoreSystemSleep()`，核对 `onStateChange` 与 `onIndicatorChange` 更新菜单和图片。隐藏状态不能留下会消费事件的绿灯命中区。
5. 如鼠标仍无效，确认正在运行的确实是新安装包，再收集该版本的实际鼠标事件与状态项几何证据；不要先恢复旧覆盖层或添加全局鼠标钩子。

当前职责划分：

- `StatusItemVisualStyle`：尺寸、周期、`hitTarget`；尺寸单位为 point，不是 Retina 像素。
- `StatusItemTilePose`：按时间计算位置、翻转角、旋转角；不依赖当前焦点屏幕的视图。
- `StatusItemIconAnimator`：向 `NSStatusBarButton.image` 写入有实际 `NSBitmapImageRep` 的彩色图片；普通动画约 30 帧／秒，定时器使用 common run-loop mode，遵守 Reduce Motion。
- `SleepPreventionController`：持有 `ProcessInfo` activity，退出时释放；明暗回调只影响表现。

已替代的类与路径为 `StatusTranslationIconView`、`StatusIconClickButton`、`SleepIndicatorButton` 及 `popUpMenu`。以搜索确认本轮没有恢复这些无效入口；这条限制只针对已失败的本项目方案，不是禁止一切 `NSButton`。

## 动效与绿灯尺寸基线

| 项目 | 当前值 |
| --- | --- |
| 状态项宽度 | `statusBar.thickness * 2`，不能固定所有屏幕都等于 44pt |
| A/文图标尺寸 | 26 × 22pt |
| 绿灯直径／命中宽度 | 8pt／18pt |
| 绿灯中心／开启休眠防护后图标中心 | 相对整个状态项中心分别偏移 −13pt／+9pt |
| 待机呼吸／连续动作周期 | 2.3s／5.76s |
| 翻转／旋转 | 每个完整动作周期各一圈 |
| 翻译中换位／环形反馈周期 | 1.1s／0.9s |
| 绿灯脉冲 | 1.3s，最大比例 2.15 |

当前待机动作在一个周期内依次为：0–24% 互换；24–42% 只翻转；42–60% 只旋转；60–78% 横移；78–100% 复位。轻微呼吸和绿灯反馈是独立节奏，不与主要动作阶段混淆。

处理“快／慢百分之多少”时明确口径：历史 `4.8s → 5.76s` 实际是**周期增加 20%**，不等同于速率减少 20%；若明确要求速率变为原来的 80%，相同动作的周期应为 `4.8 / 0.8 = 6s`。不要在总结中混用两种说法，也不要未经新请求修改已采用的节奏。

## 双屏：验证显示复制与点击，不修改系统来掩盖问题

- 回读两块显示器是否在线、是否镜像、缩放与独立空间设置。不得直接把非焦点屏幕缺图归因于系统设置，更不得自行写 `defaults` 或重启系统服务。
- 确认图片包含实际像素而非仅依赖当前窗口的子图层；当前 2× 位图让逻辑尺寸与像素尺寸分开。颜色随当前实现处理，不扩大为未经要求的外观重构。
- 本轮若涉及双屏，分别验证：屏幕甲有焦点时两屏可见；切至屏幕乙后两屏仍可见；每屏用鼠标点击都能打开菜单；绿灯显示时每屏点击绿灯只解除禁止休眠。记录具体通过和未通过项。
- 自动化只看到了菜单项或单屏截图时，不能填写“双屏通过”。

## 翻译浮层：按原生测量链路收紧布局

1. 从 `FloatingPanelController` 检查 loading、result、error 三种状态，保留鼠标附近定位、屏幕边缘限制和长内容滚动。
2. 从 `TranslationResultPresentation` 检查后端“主译／音标／候选”标签解析，保留中英文冒号、Unicode 和非结构化文本回退；不要为了排版修改翻译语义。
3. 从 `CandidateRowButton.preferredHeight(for:)` 查看实际文本宽度与测量结果，再对照 `layout()`、`CandidateRowLayout` 和父容器排布。当前最小行高 30pt、上下 inset 各 3pt，计算为 `max(30, ceil(textHeight) + 6)`。
4. 用单行与多行候选同时验收。当前测试样例：文本高 17pt 时行高 30pt；文本高 34pt 时行高 40pt。不把所有行强行压成 30pt。
5. 保留整行点击、hover、复制图标和无障碍标签；复制内容只取候选词，不连同解释、标题或音标一起复制。沿 `TranslationCandidateLink` 的 `selected-translator-candidate` 协议验证编码和回读。
6. 对比设计与实屏时使用相同结果文本和窗口尺寸。浏览器预览、静态设计或布局常量测试不能替代原生弹窗的视觉验收。
